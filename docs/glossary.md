# Glossary

Single source for terms and metric definitions used across REx. Specs and other docs
link here instead of redefining them.

## Field terms

- **AEO (Answer Engine Optimization)**: making content the answer an AI assistant or
  answer box gives to a question.
- **GEO (Generative Engine Optimization)**: making a brand appear, be described
  accurately, and be cited in answers generated by LLM-based engines.
- **AI answer optimization**: umbrella term for AEO and GEO; what REx measures and improves.
- **Answer engine / engine**: an AI system that answers questions in natural language,
  identified by `EngineId` (`chatgpt`, `claude`, `gemini`, `perplexity`, `grok`).
  REx queries engines through their APIs (with web search or grounding enabled where
  the API supports it); API answers can differ from the consumer apps.
- **AI Overviews**: Google's AI-generated search summaries. Not an API engine; planned
  as a future engine through a SERP provider.
- **AI crawler**: a bot that fetches pages for model training, AI search indexing, or a
  live user request. The list: [ai-crawlers.yaml](../packages/contracts/data/ai-crawlers.yaml).
- **llms.txt**: a Markdown file at a site's root that gives LLMs a curated summary and
  link list of the site (format at llmstxt.org). **llms-full.txt** inlines page content.
- **Schema markup / JSON-LD**: schema.org structured data embedded in a page.
- **Entity**: a uniquely identifiable thing (organization, person, product) in knowledge
  graphs such as Wikidata; **sameAs** links connect a site's entity to those profiles.

## REx domain terms

- **Org**: the tenant; billing, members and API keys belong to it.
- **Project**: one site or market tracked by an org (primary domain, locale, country).
- **Brand**: a name to detect in answers, with aliases and owned domains. Each project
  has one **primary** brand and any number of **competitor** brands.
- **Tracked brands**: the primary brand plus the competitors of a project.
- **Prompt**: a question tracked over time, phrased as a user would ask an AI assistant.
- **Prompt run**: one execution of a project's prompts across engines; produces
  prompts x engines x samples answers.
- **Sample**: one of several answers captured for the same prompt and engine in one run,
  because LLM output varies between calls.
- **Answer**: one engine's response to one prompt in one run (text + engine-reported
  sources). Immutable.
- **Mention**: a tracked brand detected in an answer (by name or alias, deterministically).
- **Sentiment analyzer**: one method that labels a mention positive, neutral or negative
  with a score: deterministic (`det:lexicon`, `det:rules`, no LLM) or LLM
  (`llm:<provider>/<model>`). Several can run side by side on the same answer.
- **Primary analyzer**: the analyzer whose result feeds the sentiment metrics;
  deterministic by default when the language is supported.
- **Lexicon pack**: the per-language data a deterministic analyzer uses (word scores,
  negators, intensifiers, rule patterns); the **lexicon registry** maps a language to
  its pack. English only today.
- **Language tag**: a BCP 47 tag such as `en` or `en-US` (`LanguageTag`); support is
  matched on the primary subtag.
- **Agreement**: how the analyzers that ran compare on a mention (majority label,
  unanimity, score spread).
- **Citation**: a URL an answer cites, either listed by the engine as a source
  (`engine_source`) or linked inline (`inline_link`).
- **Ownership** (of a citation): `own` (primary brand's domain), `competitor` (a
  competitor's domain) or `third_party`.
- **Audit**: an AI-readiness assessment of one URL, scored 0 to 100 across categories.
- **Schedule**: a cron rule that fires a target (`prompt_run`, `content_audit`).
- **Free tool**: a feature usable without login, rate limited per IP: either a public
  tool operation (sync) or an anonymous orchestrator job (audit, llms.txt).

## Architecture terms

- **Tool (tool service)**: a stateless REST service that turns a request into a
  response (for example engine-query). No database, no bus, no calls to other REx
  services. See [architecture.md](architecture.md#service-map).
- **Public tool operation**: a tool operation marked `x-rex-public: true`; the gateway
  exposes it at `/v1/tools/...`.
- **Orchestrator**: the one stateful service. Owns all data, schedules and jobs, and
  serves the dashboard and public API.
- **Module**: a bounded part of the orchestrator (identity, catalog, tracking,
  optimization, scheduling, billing, alerts, messaging) with its own Postgres schema.
- **Worker**: a stateless process that consumes jobs, calls tools and publishes results.
- **Gateway**: the thin edge: TLS, auth resolution, rate limits, routing.
- **Content extractor**: the external service (Go, built outside this repo to a
  contract REx defines) that reads websites: it turns a URL or HTML into the page's main
  content as normalized text and Markdown plus the raw page, metadata and site files;
  only workers call it
  ([content-extractor](services/content-extractor.md), [ADR 0021](adr/0021-content-extraction.md)).
- **Sitemap extractor**: the external, stateless service (Go; a separate service or an
  endpoint of the content-extractor, the implementer's choice) that lists a site's page URLs from its sitemaps, honoring
  robots.txt when asked; the only place REx discovers URLs; only workers call it
  ([sitemap-extractor](services/sitemap-extractor.md), [ADR 0023](adr/0023-llms-txt-pipeline.md)).
- **llms.txt pipeline**: the event-driven llms.txt crawl: one `sitemap-discovery` job,
  one `page-audit` job per selected URL, then one LLM-free `llms-txt-generation` job
  ([ADR 0023](adr/0023-llms-txt-pipeline.md)).
- **Page audit** (llms.txt pipeline): extraction of one page plus its page entry,
  cached and archived; not a content-auditor audit.
- **Page reference** (`PageRef`): the URL and cache keys of one page's stored results,
  carried by messages instead of the page; the reading worker gets the results from
  the cache first, then the data-aggregator
  ([page results by reference](architecture.md#page-results-by-reference)).
- **Page entry**: one page's llms.txt line (`url`, `title`, `description`), written by
  llms-txt-generator `describePage` (an LLM call only in LLM mode).
- **Data aggregator**: the external service that keeps every extracted page for
  history and analysis; workers send each fresh extraction and page entry there before
  caching it, and read page results back from it after a cache miss in llms.txt
  generation
  ([data-aggregator](services/data-aggregator.md), [ADR 0022](adr/0022-page-archive.md)).
- **SEO auditor**: Jay's external SEO auditor service, repurposed for URL-based
  structured-data checks; called by workers ([seo-auditor](services/seo-auditor.md)).
- **Membership tier**: a plan level that will set limits such as llms.txt pages per
  crawl and queue share; deferred, so today there is no page limit.
- **Extracted content**: that output as tools receive it in requests
  (`ExtractedContent`: `text` and `markdown`; with `FetchedPage`, `FetchedFile` and
  `PageMetadata` where a tool needs them).
- **Hand-off copy**: the generated, self-contained contract of an externally built
  service in `packages/contracts/handoff/`, which its owner copies into their repo.
- **Job**: one unit of work requested by the orchestrator, for example one answer
  capture (prompt x engine x sample).
- **Flow**: the sequence of tool calls a worker makes for one job type.
- **Job ledger**: the orchestrator table mapping each job's idempotency key to its
  subject, status and attempts.
- **Idempotency key (job)**: a deterministic key that identifies a job, so duplicates of
  it or its result are applied once.
- **Message**: one JSON envelope on the bus; its `type` is `<job>.<requested|completed|failed>`.
- **Routing key**: the key a message is published with on `rex.events`: its type plus an
  optional shard (for example the engine).
- **Queue**: a durable quorum queue per consumer and job (`rex.<consumer>.<job>[.<shard>]`).
- **Outbox / inbox**: orchestrator tables that make publishing atomic with state changes
  and consuming idempotent.
- **Reconciler**: the orchestrator loop that republishes jobs with no result by their
  deadline.
- **Retry delay queue**: a queue (`rex.retry.<delay>`) a failed job waits in before going
  back to its queue; which delays and how many retries is configurable per queue.
- **Dead letters**: messages rejected or redelivered too often, parked in
  `rex.dead-letters` for an operator.
- **Service token**: a short-lived JWT the gateway uses for the orchestrator's internal
  endpoints. Tools take no tokens.
- **Vendored contract**: a generated, self-contained copy of a contract inside a service
  folder (`contract/`), regenerated from `packages/contracts` and drift-checked in CI.
- **Tool template**: the template of a tool's language (`services/_template` for
  TypeScript; `_template-python` and `_template-go` once added), from which
  `scripts/new-tool` generates a tool's boilerplate; each copy is tracked in the tool's
  `.template.json`.
- **Tool language**: `ts`, `python` or `go`, set per tool as `language` in
  [vendoring.yaml](../packages/contracts/vendoring.yaml) and chosen by the tool's own
  ADR ([ADR 0024](adr/0024-per-tool-language.md)); callers never depend on it, only on
  the contract.
- **Language bring-up**: the Python or Go parts of Phase 1 (type generator, validation
  spike, template, CI lane), done right before the first tool in that language (Python:
  Phase 2; Go: Phase 7)
  ([roadmap](roadmap.md#phase-2-tool-services-one-at-a-time-each-built-and-tested-in-isolation)).
- **LLM mock mode**: `LLM_MODE=mock`, in which a tool's LLM adapter answers from
  recorded fixtures (no keys, no network, no cost).
- **Usage**: the per-LLM-call token and cost report every tool returns.
- **Cache first**: no tool is called before the shared cache is checked; workers and the
  gateway do this through `@rex/cache` ([ADR 0016](adr/0016-cache-first.md)).
- **Cache key**: the identifier of one stored tool response, derived as defined in
  [cache/policy.yaml](../packages/contracts/cache/policy.yaml).
- **Cache mode**: `use`, `refresh` or `bypass` for one call or job (`CacheMode`).
- **Cache outcome**: what happened to one tool call: `hit`, `miss`, `refresh`, `bypass`
  or `uncacheable` (`ToolCallCache`).
- **Window**: a cache period aligned to UTC (for example one day for engine answers)
  after which a new answer is fetched.
- **Variant**: a number in the cache key that keeps otherwise identical calls apart, such
  as the samples of one prompt.
- **Cache scope**: who shares a cache entry: `shared` (every customer, the default) or
  `tenant` (one organization) (`CacheScope`).
- **Cache override**: a per-environment or per-customer change to an operation's scope,
  TTL or window; how overrides combine is defined in policy.yaml `resolution`.
- **keyVersion**: per-tool number in policy.yaml, bumped when a tool's output changes for
  the same input, which retires its old cache entries.
- **Deterministic first**: prefer a non-LLM method where one is feasible; LLM methods
  are optional and comparable by model ([ADR 0017](adr/0017-deterministic-first-analysis.md)).

## Metric definitions

Over a set of answers *A* (filtered by project, time range and optionally engine), with
tracked brands *B*:

| Metric | Definition | Range |
|---|---|---|
| **Mention rate** (brand visibility) | answers in *A* that mention brand *b* / \|*A*\| | 0 to 1 |
| **Share of voice (SoV)** | answers in *A* mentioning *b* / sum over all *b'* in *B* of answers in *A* mentioning *b'* | 0 to 1; sums to 1 across *B* when any brand is mentioned |
| **Average position** | mean of *b*'s position over answers that mention *b*, where position is the 1-based rank of the brand's first mention among tracked brands in that answer | 1 or more; null if never mentioned |
| **Sentiment score** | mean per-mention score of the primary analyzer, from -1 (negative) to 1 (positive); label `positive` above 0.25, `negative` below -0.25, else `neutral`. Comparison views compute the same per analyzer | -1 to 1; null if never mentioned or no analyzer ran |
| **Citation share** | answers in *A* citing at least one URL of domain *d* / \|*A*\| | 0 to 1 |
| **Audit score** | weighted mean of category scores (weights set by content-auditor, published in its doc) | 0 to 100 |

Samples count as separate answers in every metric.
