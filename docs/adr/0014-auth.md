# 0014: Auth: one issuer in the orchestrator, no auth inside tools

- **Status:** Accepted (2026-11-22, accepted by Jay)
- **Date:** 2026-11-22
- **Deciders:** Jay Pascual
- **Amended:** 2026-11-22: API-key token cache lives in the gateway's `redis-edge` instance (allowed while Proposed; see [README](README.md))
- **Amended:** 2026-11-22: tools contain no token verification; access to tools is enforced in front of them ([ADR 0018](0018-tool-portability.md))
- **Supersedes:** [0005](0005-auth.md)

## Context

Callers are dashboard users, API clients, the gateway and workers. Tools have no
database and no tenant context. The first version made tools verify service tokens
offline, which put an auth library, key configuration and token minting into every
tool and its tests; that conflicts with tools being self-contained projects
([ADR 0018](0018-tool-portability.md)).

## Decision

- **The orchestrator's identity module is the only token issuer.** One JWT format
  (EdDSA, rotated keys, public keys at `/.well-known/jwks.json`). Claims: `iss`, `sub`,
  `typ` (`user`, `api_key`, `service`), `org` (not for service), `role` (users) or
  `access` (API keys), `iat`, `exp`, `jti`.
- **Users:** email and password at `/v1/auth/*` (Argon2id). Access token 15 minutes,
  opaque refresh token 30 days, rotated on every use with reuse detection. One org per
  token; `POST /v1/auth/refresh {orgId}` switches.
- **API clients:** `X-API-Key: rex_live_<32 base62>` (or `rex_test_`), stored hashed,
  shown once, `read` or `read_write`. Only the gateway accepts raw keys and exchanges them
  at `POST /internal/v1/api-keys/exchange` for a token of at most 5 minutes, cached in
  the gateway's `redis-edge`. Revocation is enforced at once by the orchestrator, which checks the key's
  status on every `api_key` token; the gateway cache only bounds exchange traffic.
- **Service tokens** are only for the gateway's calls to the orchestrator's internal
  endpoints: it obtains them with client credentials at
  `POST /internal/v1/service-tokens` (`typ: service`, `sub: svc:gateway`, 15 minutes).
- **No auth inside tools.** Tool specs declare `security: []`; tools verify no token,
  carry no auth dependency or key configuration, and never receive user tokens or
  tenant IDs. Access is enforced in front of them:
  - **Network policy** (Kubernetes `NetworkPolicy`, default deny): a tool accepts
    ingress only from pods labelled `rex.io/kind` = `workers` or `gateway`, plus
    kubelet probes. Tools have no Ingress or public Service.
  - **Gateway:** the only internet path to a tool; it routes only `x-rex-public`
    operations, rate limits them and strips inbound headers.
  - **Optional sidecar mTLS** (service mesh) can be added later without touching tools
    ([deferred](../roadmap.md#deferred-decisions)).
- The orchestrator verifies tokens with `jose`, enforces per-operation security from its
  spec (some anonymous), checks role/access and scopes every query to `org`; the gateway
  verifies access tokens with `jose` and the cached JWKS.
- Roles are org-wide: owner, admin, member, viewer.

## Consequences

- One key set and one issuer; only the gateway and the orchestrator verify tokens.
- Tools are simpler to build, test and run anywhere: no keys, no token minting in tests.
- No user context reaches tools, so a compromised tool cannot act as a tenant. A
  compromised pod inside the cluster that is allowed by the network policy (a worker or
  the gateway) can call tools; tools hold no data and no tenant context, so the damage
  is limited to compute and LLM spend, bounded by the spend limits set on each
  provider's API keys.
- SSO and per-project permissions are later additions to the identity module.

## Alternatives considered

- **Service tokens verified inside each tool** (first version): defense in depth, but
  every tool needs an auth library, keys and token minting in tests, and cannot be
  developed on its own.
- **Third-party identity (Auth0, Clerk, Cognito)**: faster start, recurring cost and less
  control over API-key exchange and service tokens.
- **mTLS / service mesh identity**: enforced by a sidecar, so it needs no tool code; kept
  as an optional later layer.
