# Roadmap

Build in phases. A phase is done only when every line of its **Done when** is true.
Do not start a phase before the previous one is done; inside a phase, independent
services can be built in parallel. Each service must also meet the
[service definition of done](#service-definition-of-done).

**Tools first, platform after.** Tool development is the top priority. Tool services
are request-in, response-out functions, and each one is a **self-contained project**
([ADR 0018](adr/0018-tool-portability.md)): its folder installs, builds, tests and runs
in Docker on its own, with public packages of its language (TypeScript, Python or Go,
[ADR 0024](adr/0024-per-tool-language.md)) and a vendored contract. So development
starts with the machinery that makes that true (Phase 1), then the tools one by one
(Phase 2). The platform (orchestrator, gateway, cache integration, bus, workers) comes
after and only wires the finished tools together.

### 1.3 Spikes: request validation from the vendored 3.1 spec

One question per language: can a tool serve its vendored 3.1 spec so that the spec, not
hand-written schemas or code-first models, validates every request, with JSON Schema
2020-12 semantics? Every spike uses the vendored answer-analysis spec, which has the
hardest features: `unevaluatedProperties: false` with `allOf`, `type: [x, 'null']`,
`oneOf` with null, `propertyNames`, `uniqueItems`, defaults, `pattern` with lookahead,
internal `$ref`s after bundling. Every spike is a throwaway project (not merged into a
tool) and ends with a short ADR.

Deliverables:
- **TypeScript (Phase 1, time-boxed: 2 days).** Candidates: (a) `fastify-openapi-glue`
  with an `Ajv2020` validator compiler set through `setValidatorCompiler`; (b) a
  60-line route loader in the template that reads the bundled spec and registers routes
  with `Ajv2020` schemas. Ajv settings fixed for REx: `strict` on with OpenAPI keywords
  (`example`, `x-rex-*`) declared, `allErrors`, formats from `ajv-formats`, **no**
  `removeAdditional` (unknown fields must give 400), **no** type coercion for JSON
  bodies, `useDefaults` on (matches the cache key rule "apply defaults first").
  Response side: `fast-json-stringify` does not cover all 2020-12 keywords, so check
  whether to keep it per route or switch to `JSON.stringify` via
  `setSerializerCompiler`; responses are validated against the spec in contract tests
  either way. Error mapping: Ajv errors to `Problem` with `code: validation_failed` and
  `errors[].pointer`. ADR 0020 records the choice and the Ajv options.
- **Python (time-boxed: 2 days; runs in the Python bring-up, right before Phase 2
  step 5).** Confirms Jay's choice, openapi-core's FastAPI middleware with
  `V31RequestValidator` (ADR 0024); only if it fails, a 60-line route loader over
  `jsonschema`'s `Draft202012Validator` reading the bundled spec is tried as the
  fallback. Same REx settings (unknown fields 400, no coercion of JSON bodies, defaults
  applied, formats checked), the same error mapping, and datamodel-code-generator models
  checked to be types only. The next free ADR number records the result.
- **Go (time-boxed: 2 days; runs in the Go bring-up, right before ai-traffic-analyzer in
  Phase 7).** Confirms Jay's choice, kin-openapi `openapi3filter` with JSON Schema
  2020-12 validation (3.1 support landed in 2026; ADR 0024); only if it fails,
  libopenapi-validator is tried as the fallback. Same REx settings and error mapping;
  oapi-codegen types and embedded spec generated from the bundled 3.1 file. The next
  free ADR number records the result.

Done when (per spike): the same table of 25 request cases (valid and invalid, one per
feature above, shared as a JSON file by all three spikes) gives the expected 200 or 400
with correct pointers on the chosen option; a valid response fails contract validation
when a required field is removed, and its ADR is accepted. The TypeScript per-tool
CI gate uses 5 ms p99 per MiB of the effective request body limit. [ADR 0027](adr/0027-scale-typescript-validation-budget.md)
amends the budget set by [ADR 0026](adr/0026-typescript-validation-budget.md).
The Python and Go bring-up spikes use the budgets in [ADR 0024](adr/0024-per-tool-language.md). Each spike is a gate: the first tool in its
language starts only after it passes. A Python or Go spike that fails, with its fallback
too, leaves that tool in TypeScript (its tool ADR says so); ADR 0020 is required for
Phase 1, the others only for their bring-up.

### 1.5 CI with the portability check

Deliverables (GitHub Actions, reusable workflows):
- `contracts`: Redocly lint, AsyncAPI validate, `check-contracts`,
  `vendor-contracts --check`, `gen-docs --check`.
- `tool` (matrix over changed tool folders, and over all tools when a template,
  vendoring.yaml or a contract changes; each matrix entry reads the tool's `language`
  and runs that language's lane): template drift, then
  - `ts`: `npm ci`, ESLint, `tsc`, vitest with coverage, dependency-cruiser ("no import
    resolves outside `services/<tool>/`"), package.json lint (exact versions, no
    `workspace:`/`file:`/`link:`/`portal:`, no `@rex/*`, runtime packages from the
    TypeScript table);
  - `python` (wired in the Python bring-up): `uv sync --frozen`, ruff, mypy (strict),
    pytest with coverage, import-linter (layers; provider SDKs only in the LLM adapter),
    pyproject lint (`==` pins, no path, git or editable sources, runtime packages from
    the Python table);
  - `go` (wired in the Go bring-up, Phase 7): `go mod verify`, golangci-lint (gofmt, govet,
    depguard: provider SDKs only in `internal/llm`, modules from the Go table), `go
    test` with coverage, go.mod lint (no `replace`, no local paths).
- `portability` (same matrix, one language-neutral job): copy the tool folder to
  `$RUNNER_TEMP/<tool>` (outside the checkout, with no parent manifest, lockfile, cache
  or config), run the language's install, build and test commands (from the tool's
  `AGENTS.md` block) with `LLM_MODE=mock` and outbound network blocked after the
  install, then `docker build`, `docker run` and a `/healthz` probe within 10 s.
- `jscpd`: one run across all languages; per-folder threshold 3 % and 50 tokens;
  cross-tool run that ignores files listed in `.template.json`, `contract/**`, test
  fixtures and reports any clone of domain code.
- The CI workflow's `Required` check collects the contract, matrix, portability,
  and duplication results. Follow the [Git workflow](../AGENTS.md#git-workflow)
  before merging to `main`.

The workflow selects the matrix with `scripts/tool-ci matrix --base <commit-sha>`.
The same comparison scopes `scripts/tool-ci duplicates --base <commit-sha>`.
`scripts/portability-tool <name> ts` runs the standalone check on Linux with Docker.
The template participates in full-matrix runs. Generated contract-only tool folders
join the matrix after scaffolding.

Done when: a PR that changes only one tool runs only that tool's jobs and finishes in
under 10 minutes; each of these deliberate violations, in its own PR, fails the right
job with a message naming the file: a `workspace:*` dependency, an `@rex/` dependency,
an import of `../../packages/...`, a hand-edited `contract/openapi.yaml`, a source spec
change without re-vendoring, a `security` scheme in a tool spec, a test that needs a
real API key, a template file edited without `owned`, a copied domain function between
two tools, a tool whose `language` is not `ts`, `python` or `go`; the matrix shows the
`python` and `go` lanes as defined but skipped until their bring-ups; each bring-up
later proves its lane with the same violations in its language (a path source in
`pyproject.toml`, a `replace` in `go.mod`, an import outside the folder).

**Phase 1 done when:** all five items meet their done criteria (TypeScript parts);
`services/_template` passes the portability job; Jay can create a new TypeScript tool
with one command and hand its folder to someone without repo access; the Python and
Go parts are written down as bring-up checklists (1.2 generator, 1.3 spike, 1.4

- The page archive: workers send every fresh extraction to the external

## Phase 6: Monetization

per org is visible; visibility and citation alerts fire; weekly reports are delivered.

## Phase 8: Production hardening

## Service definition of done

- Its OpenAPI file in `packages/contracts/openapi/services/` reviewed, lint-clean,
  `$ref`s common.yaml; vendored copies regenerated and committed.
- **Tool:** no state, no cache, no bus, no auth, no calls to other REx services; every
  LLM call through its LLM adapter and reported in `usage`; a deterministic method where
  feasible; passes the portability job (its folder alone: install, build, test, Docker);
  public packages of its language only, from its table in conventions §16; no template drift except `owned` files; cache policy entry
  present and `keyVersion` bumped when outputs change.
- **Orchestrator module:** owns its schema and migrations; publishes only through the
  outbox; result handlers idempotent (inbox + job ledger).
- **Worker flow:** messages added to events.yaml and topology.yaml; every tool call
  through `@rex/cache`; acks only after the result is confirmed; retryable vs final
  errors classified.
- Unit tests for domain logic, contract tests for routes (responses validated against
  the spec), message tests against events.yaml.
- `/healthz` and `/readyz` work; logs and traces carry the standard fields.
- Service doc in `docs/services/` up to date; README env table generated.
- Own Dockerfile; deploys independently.
